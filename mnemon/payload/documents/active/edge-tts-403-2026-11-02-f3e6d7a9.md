# 语音朗读插件选型与 Edge TTS 403 修复（2026-11-02）

群友在 QQ 群问「dsh-voice-mode 这个插件行不行」，随后追问「dsh-plugin-xiaomi-mimo-tts 还有这个插件，你看哪个更合适」。实际目标是给现有 DSH / 腾讯官方 qqbot 链路加朗读与 QQ 语音，不是网页语音对话。相关前情见 c51d380c-d546-4c0a-bb44-1f501e7c187a（2026-10-22 装 @memef1f1y/dsh-plugin-tts）与 a3dadfaf-af3b-4b3c-9696-7c21aaf698ec（SiliconFlow 克隆音色发 QQ 语音）。

## 三个候选的定位

- **dsh-voice-mode 0.7.34**：网页端全双工语音——流式识别进可编辑草稿、停顿自动发送、按句朗读 + 实时字幕、开口打断（真 barge-in）。与「从 QQ 发语音」是两件事；本地识别要下模型（如 FunAudioLLM/SenseVoiceSmall），手机上跑起来偏慢。默认朗读走 Edge 云端，也可切本地 VITS / Kokoro（Kokoro 是 sherpa-onnx 原生 addon，桌面 Electron 下需系统 PATH 有 Node ≥18 或 DSHVM_NODE）。结论：整插件对 QQ 场景不适用，但 Edge 引擎可以单独借用。
- **dsh-plugin-xiaomi-mimo-tts**：npm 上不存在（E404，连 README 都取不到）。实际包名是 **dsh-xiaomi-tts@4.2.8**。engines 为 dsh >=0.2.1-0 <0.3.0-0、node >=24.9.0；本机 DSH 0.2.1-rc.4、node v24.22.1，对得上。支持小米 MiMo、豆包 Seed TTS、内置/自定义/复刻音色、浏览器语音兜底，与官方 dsh-qqbot 插件有联动，可直接发 QQ 语音。安装：`dsh plugin --profile web add dsh-xiaomi-tts@latest`。
- **LotusPrimeUmbra/dsh-plugin-tts**：功能更多（小米 MiMo / Breeze 双协议、克隆、唱歌、自定义请求模板、参考音频管理），零 npm 依赖。但语音发送走本机 OneBot HTTP 网关（SnowLuma 默认 http://127.0.0.1:3000），与当前用的腾讯官方 qqbot 插件不是一条线；要接 QQ 得改桥接白名单，加入 tts_speak / tts_voices。接入成本明显更高。

## 倾向

选 **dsh-xiaomi-tts**，前提是用户去申请一个 key：小米在 platform.xiaomimimo.com，豆包在火山引擎语音控制台，均可免费申请。若不愿开账号，就继续用 Edge 免费音色；若坚持保留自己的克隆音色，则沿用 SiliconFlow 那条线（见 a3dadfaf 文档）。

## Edge TTS 403 排查与可用组合

- 现象：合成 WebSocket `wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1` 返回 HTTP 403（插件内旧打包 msedge-tts，Sec-MS-GEC-Version=2-143.0.3650.96）；但音色列表接口正常（200，170991 字节），说明网络与 token 本身没被封。
- 可用组合：改用 msedge-tts 2.1.1 的 hashSecMsGecV2（SHA-256 摘要 + cs64 混淆，消息前缀 EDGE_COPYRIGHT），配 Chrome/143 的 User-Agent 与 `Origin: chrome-extension://jdiccldimpdaibmpdkjnbmckianbfold` 后，合成成功，得到 17–18 KB 的 mp3。
- 已在群里发出两条试听：zh-CN-XiaoxiaoNeural（晓晓，干净标准）与 zh-CN-XiaoyiNeural（晓伊，偏软）。两者是微软音库，不是用户自己的音色；5 秒录音克隆出来的更像但发虚。
