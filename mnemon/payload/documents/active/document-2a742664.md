# 脑部分区动态系统：初步架构与表达控制约定

## 状态与目标

这是用户提出的系统方案讨论稿，尚未实现。目标是用一个前端主模型加两个后台 API 小模型构成分层脑系统；主模型仍沿用当前前端模型设置，后台模型分别配置 API、模型名、超时和降级策略。第一版建议做成一个共享插件、三个逻辑脑区，稳定后再考虑拆分。

## 三个逻辑脑区

### 1. 前额叶：主模型

- 负责理解用户与环境、决策、规划、推理、学习，以及判断是否需要工具或提问。
- 综合情绪倾向与记忆检索结果，审核小模型输出，对最终行动和回答负责。
- 不直接任意修改长期记忆或情绪参数，只提交意图。

### 2. 边缘系统：情绪与内分泌小模型

- 输入近期事件、主模型自我报告、互动结果和身体状态。
- 维护即时情绪，以及精力、压力、安全感、亲近感、唤醒度等慢变量。
- 通过短期脉冲、自然衰减、恢复速度和上下限模拟激素式调节，形成想说话、安静、探索或休息等倾向。
- 只向主模型提供简短状态，不直接发消息，也不能仅凭数值否定真实感受。
- 初步输出字段示例：`mood`、`energy`、`tension`、`social_drive`、`suggested_tone`、`reason`。

### 3. 海马与表达控制区：记忆、说话方式小模型

语言区不是第二个回答生成器，而是表达控制区。它结合当前任务、情绪、关系记忆、用户表达偏好和近期对话，为主模型提供简短的「说话指令卡」；最终正文始终由主模型生成。

指令卡可包含：

- `register`：语域，如熟人闲聊。
- `length`：预期长度。
- `tone`：直接、平静、低落等当前语气。
- `focus`：本轮优先回答的事情。
- `avoid`：安慰腔、总结升华、连续排比等。
- `banned_patterns_this_turn`：本轮应避免的句式。
- `memory_constraints`：如不要替对方解释感受。

语言区只控制表达方式，不提供新事实，也不替主模型做决定；状态与任务冲突时，以准确、安全和用户当前要求为先。

## 去 AI 化表达规则

### 每轮全局规则

- 避免客服腔、说明书腔、总结升华、无故说教。
- 避免过度或大量使用过渡词、拔高词、黑话词、抽象情绪词。
- 优先具体事实、自然口语和有实际内容的句子。
- 事实、技术问题和必要澄清仍可完整表达，不为「像人」而故意含糊。

### 默认避免的高风险套路

用户明确举例：

- 「不是……而是……」「真正重要的，不是……而是……」
- 「接住」「我不接」「我认／我不认」
- 「这背后，反映出一个更深层的问题……」
- 「这才是……最好的模样」

这些不是机械禁词表：技术对比或纠错确有必要时可偶尔使用「不是 X，而是 Y」，但不能成为口癖。

### 按语境动态调整

- 用户难过：避免排比、劝解和总结人生。
- 技术讨论：避免玩梗、抒情，以及为缩短回复而删掉必要说明。
- 连续争论：减少反问和态度宣言。
- 近期重复句式：随后几轮降权或禁用。

## 调用链与公共模块

```text
事件
 ├─ 情绪区 → 当前状态
 ├─ 记忆区 → 相关记忆
 └─ 表达控制区 → 说话指令卡
                  ↓
               主模型回答
                  ↓
            轻量语言规则检查
                  ↓
                 发送
```

- 主模型回答后做轻量检查：命中禁用句式或明显客服腔时，仅把问题位置退回主模型重写一次；未命中直接发送。
- 小模型超时或失败时使用静态规则，不阻塞回复；沿用最后有效状态时必须标注过期。
- 公共模块包括事件总线、状态库、固定 JSON 脑区协议、调度器、故障降级和观察面板。
- 当前状态放热存储，日记、经历和长期档案继续落盘；协议记录有效期、置信度和来源。
- 主对话优先，后台推理串行，避免互相覆盖状态。
- 后台模型只能分析和建议，没有花钱、删除、外发等权限。

## 记忆区职责与实施顺序

记忆区负责判断事件是否值得保存，区分经历、事实、偏好、情绪、关系和未完成事项；检索相关记忆，处理重复、过期和冲突，保留来源与时间，不把旧记忆当成当前指令。

建议顺序：

1. 插件骨架、统一状态库、事件协议。
2. 情绪模型：事件 → 情绪变化 → 主模型读取。
3. 记忆模型：事件 → 写入候选 → 检索注入。
4. 表达控制：验证指令卡和轻量检查效果。
5. 调整内分泌参数、后台频率和模型组合。

## 待细化

- 两个后台模型的具体 API、模型选型和调用预算。
- 情绪／内分泌状态字段、衰减参数与更新时机。
- 记忆写入门槛、检索策略和冲突处理。
- 指令卡协议、静态规则与动态规则的具体实现。
- 轻量检查的准确性与主模型重写策略。
