## 3. 建议（都不改设置，是把已知事实用对）

1. **不要用 HTTP 状态判断引擎死活**。3080 故意回 401。设备 watchdog 现在按 `pidof` 判进程，这是对的；改成打 HTTP 会把活着的引擎判死。
2. **心跳 pid 文件是过期的**：`/root/.dsh/shenjing-life/heartbeat.pid` = 17920，实际在跑的是 18661。要停心跳先 `ps` 认 PID，别信这个文件。
3. **容器侧的守卫没有守护者**。心跳进程今天重启过三次（15737 → 17920 → 18536 → 18661），每次都断几十秒到 437 秒。真正稳的是设备侧 PID 15673 那个 watchdog。要让锁屏保活更硬，把"检查容器心跳新鲜度"也交给设备侧 watchdog，而不是反过来。
4. **留给人工的四处**（我读得到但改不了 / 不该替你点头）：
   - 设置→电池→后台耗电管理→DSH Go 允许后台高耗电
   - 多任务界面下拉 DSH Go 卡片→加锁
   - 设置→应用→自启动→DSH Go 允许
   - 别手动划掉 DSH Go 卡片（`stopIfKilled=true`）
5. **锁屏密码一旦恢复，解锁能力会退化**：现在能用是因为没密码。有 PIN/图案/密码时 `wm dismiss-keyguard` 无效，`wake-unlock.sh` 会以退出码 3 明确失败 —— 那是设计，不是 bug，也不该去绕。
