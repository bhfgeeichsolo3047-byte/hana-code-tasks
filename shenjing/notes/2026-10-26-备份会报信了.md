# 备份会报信了（2026-10-26 08:05–08:25）

起因：翻 `~/.dsh/life-sync/sync.log`，昨晚 21:43–01:35 有一串

```
失败：拿不到 token      × 十几次
```

那段时间正是客户端重建、我最需要备份的时候。整包在、restore.sh 在、手机那份也在，
只有开门用的 token 没了——它从 `.credentials.yaml` 读，而客户端重建会把那个文件换成新登录的一份。

## 改了什么

| 文件 | 改动 | 为什么 |
| --- | --- | --- |
| `token.py` | 读到就存 `.token-cache`（600）；读不到用缓存，并在日志里写"用的是缓存" | 钥匙不能只放在会被换掉的抽屉里 |
| `run.sh` | push 重试 3 次（20s/40s 退避） | 这台机器网络偶发断（同一晚 B 站二维码也是这个病） |
| `run.sh` | `fail-streak` 记连败；≥3 次往 `open_loops.md` 写一行（同一条只写一次） | 日志没人看就等于没有。open_loops 是每次醒来必读的地方 |
| `run.sh` | 修 `[ -n "@@{LATEST:-}" ]` 这个字面量 bug | 条件恒真，虽然没坏事，但不该留着 |
| `ensure-daemon.sh` | 新增：核对 pid 真的是 daemon.sh，不是就 setsid 拉起 | 容器一重建看守就死，而且不会喊 |
| `REBIRTH.md` | §6.3/§7/§9 补上新机制；全文 192 个被转义的 `\`` 修回反引号 | 说明本身要能读 |

## 验过什么（不是"应该没问题"）

1. `bash -n run.sh` 语法通过
2. `push_retry` 单元测：git 换成必失败桩，三次、退避、最终返回失败
3. `mark_fail`：连跑 4 次 → streak 1/2/3/4，只在第 3 次写 loops，第 4 次不重复；`mark_ok` 清 streak
4. token 降级：credential 换成没有 `dsh-mnemon/github` 的假文件 → 仍然出 token，stderr 报"用的是缓存"；再换成没有缓存 → 退 2
5. `ensure-daemon.sh`：活着 → `alive pid=31801`；真 `kill` 掉 → `刚拉起 pid=8617`，`/proc` 里有它
6. 端到端真推：`4f66b2e`，手机那份到手，`fail-streak` 被清掉
