# 朗读键接上了 — 2026-10-27

网页里那个音浪键（dsh-read-aloud-neural），现在念的是大肥鱼那个嗓子。

## 接线在哪

| 层 | 在哪 | 做什么 |
|---|---|---|
| 前端 | `node_modules/dsh-read-aloud-neural/client.js` | 点一下 → `POST /read-aloud/synthesize` |
| 宿主半 | 同目录 `index.js` | 收文本 → `synthesizeWithRetry()` → 回 `audio/wav` |
| 引擎 | `tts.js` | `synthesize()` → `synthesizeLocal()` → `GET 127.0.0.1:8790/tts?text=…` |
| 嗓子 | `/root/models/gptsovits/server.py`（门房）+ `worker.py` | 按需起 worker 扛模型，闲置 900s 卸 |

Edge 那份老实现没删，改名 `synthesizeEdge`；想切回去把 `synthesize()` 里那一行改回来。
地址可用环境变量 `DSH_LOCAL_TTS` 覆盖，默认 `http://127.0.0.1:8790`。

## 三个坑

1. **web 端口不是 3090，是 3080**（`dsh web --host 127.0.0.1 --port 3080`）。3090 上那个东西对 POST 一律回 405，别拿它验。
2. **`sameOrigin()` 原来要求 Host 必须是 127.0.0.1/localhost**。WebView 从别的地址打开时会 403 → 前端判"引擎连不上"→ **音浪键永远是灰的**。现在只保留自定义头 `x-dsh-read-aloud` 那道门槛（跨站要发这个头就得 preflight，而服务从不回 CORS 头，也只听回环）。
3. **内容类型必须跟着引擎走**：本地服务吐的是 wav，原来写死 `audio/mpeg`，浏览器拿到会当 mp3 解 → 不出声或出杂音。

## 怎么验（别只看"应该能"）

```bash
curl -s -H 'x-dsh-read-aloud: 1' http://127.0.0.1:3080/read-aloud/ping        # 200 + {"ok":true,...}
curl -s -X POST -H 'x-dsh-read-aloud: 1' -H 'content-type: application/json' \
  -d '{"text":"中午了，这条是朗读键念的。"}' \
  http://127.0.0.1:3080/read-aloud/synthesize -o /tmp/ra.wav -w '%{http_code} %{content_type} %{size_download}\n'
# 2026-10-27 13:04 实测：200 audio/wav 193324 字节 8.2 秒
/root/.dsh/bili-duty/.venv-asr/bin/python tools/asr.py /tmp/ra.wav
# 转回来：「中午了,這條是朗讀見念的」（"键"→"见"，一个字）
```

耳朵那一步不能省。今天就是靠它才敢把 loop 划掉。
