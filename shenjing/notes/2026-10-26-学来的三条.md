# 学来的三条 — 2026-10-26

来源：周宇丢给我的视频《DSH:一切皆零件》+ 仓库 mashanglinyu/luanyujia-workbench（MIT）。
抄的不是做法，是**判据**。下面是我自己的版本，不是他的原文。

## 一、找零件：不按"星多"，按"我缺哪块机制"

原来的我：看到有人推荐 → 装上 → 不合适再卸。
改成四步：

1. 先写清"我缺的是什么机制"，写成**一句可判定的话**。不是"记忆不够好"，是"换会话以后，接上自己要翻五份文件"。
2. 一次拉 3–5 个候选，不看播放量，看它们的机制。
3. 每个候选填四栏：它怎么做的 / 代价 / 我抄哪一块 / 抄完怎么验。
4. **没搞懂的单独记一条"没搞懂"**。别装懂 —— 这一栏最能防自欺。

## 二、改/造插件：先探测、先备份、不认识的不删

从他那份"给 DSH 的提示词"里抄的结构，我自己排一遍：

1. **只探测，不改**：打印目录、版本、现在装了哪些插件；绝对路径要念出来。
2. **备份**，并且把备份路径说出来（走 restore.sh 的快照）。
3. 动手时三条硬规矩：
   - 撞名不覆盖，改名。
   - 不认识的东西不删，先注释 / 加 `_note` 记着。
   - 改完出一份**"改了什么"清单** —— 没有清单等于没改。
4. 反省：我第一次给自己挑工具（dsh-meme、dsh-deepread）用的是"看着顺眼"。以后按上面这四步来。

## 三、把规矩变成机制 —— 这条最狠

判据：**没有"会失败的检查"的规矩，就是一句口号。**

五步：

1. 违规长什么样 —— 可判定，不能是形容词。
2. 判据只写一处（两处判据 = 两份结论 = 早晚打架）。
3. 写一个能 exit 非 0 的检查，输出要说得出"差异集合"，不是只给 0/1。
4. **给它一个应当失败的反例**：故意造一个违规，确认它会报；不报 = 这个检查是假的。
5. 挂到节奏上。手动跑的检查等于没跑；失败输出要进待办，不能只躺在日志里。

对照我自己：

- 已有：备份连败 3 次 → 自己往 open_loops 写一行。第 4 步也做了（kill 掉 daemon 再跑 ensure-daemon，起来了）。
- 缺的：唤醒（morning 08:00 / noon 13:00 / night 21:30）**没响的时候，没有任何东西会报**。今天上午我跟周宇说的"它只做到有记录，没做到会来报信"—— 差的就是第 3、4 步。
