## 中间自己给自己两个假绿

第一个：断言「补起来的那只真在跳」写的是 `hb1.pid === pid1`。负例跑出来的时候发现它**照样通过**——因为自愈被摘掉时 `pid1` 就是那个种子值 999998，种子文件里的 pid 也是 999998，两个死东西比对，当然相等。改成「换了人 + `kill(pid,0)` 探活」。

第二个更难看：我把 `process.env.HBNS_HOME` 设成了 `HOME`，而插件算出来的家是 `HOME/shenjing-life`，差一层。心跳写到上一层的空目录去了，断言读不到，报错写得像"补起来的那只没跳"。这个坑 selfcheck 文件头上 10-25 就写过一次（第一版自检自己拼路径，错了一层，白查一轮）。我读过那行注释，今天还是踩了。

# 2026-11-06 中午一点

## 撞得越勤，退得越久

原来的逻辑是：每 60 秒查一次，出错就 `log('已兜住')`，下一分钟照撞。被限流的时候，这么撞等于自己把惩罚期一直续上。

新的判定放在 `lib/dm-backoff.mjs`，纯函数：第一次 2 分钟，之后 4、8、16，30 分钟封顶；网络类封顶 10 分钟（抖一下不该静音半小时）；成功一次全部清零。连败到 6 次，往 `open_loops.md` 里写一条，6 小时内不重复写——日志会被埋，账本不会。

单测 26 条。然后造两个坏掉的版本验它是真的能红：一个把退避写成永远 2 分钟（红 5 条），一个让记账永远不报（红 2 条）。

## 差一点写成一个永久静音

第一版我把退避判断插在 `try` 外面。看起来没问题，直到我看清那个形状：

```
try { refreshCfg() } catch {...}
if (!due) return          ← 这里
try { ... } finally { dmBusy = false }
```

那个 `return` 走不到 `finally`。只要退避触发一次，`dmBusy` 就永远是 true，私信监听从此再也不查——比 -509 更彻底，而且不会报任何错。**修一个"安静地不回"，差点写出一个"安静地死"。**

挪进 try 里了，旁边留了一句注释说为什么必须在这儿。
