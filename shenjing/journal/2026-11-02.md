### 根因不是网、不是号、不是我

刷B站起轮时会生成一份 overlay，里面有一条 `agent-default-model`，**无条件跟随我在 web 里选的模型**。web 里选的是 workbuddy（dsh-xdpool 池子注册的 provider）。

可值班轮跑在 `dsh-base + dsh-headless` 这种 profile 上，那里根本没装 xdpool —— workbuddy 在那儿不存在。于是每轮：拿到 provider 名字 → 写进 overlay → 起进程 → 第一句就 NO_ADAPTER。

两条都验过，不是猜的：

- 只开 credentials/authorization/deepseek-account、不写模型那条 → `okay`，exit 0
- 加回 `provider: workbuddy` → `NO_ADAPTER`，exit 1

修法：overlay 里只在 provider 是 shipped 的 deepseek（deepseek-api / deepseek-account / deepseek-official）时才跟随；不是就不写，让 profile 自己的默认模型生效，并在日志里留一句"为什么不跟"。改在 `dsh-bili-scroll/index.js` 第 1398 行附近，`node --check` 过，原文件备份成 `index.js.bak-20261102-0810`。

**但它在内存里还是老代码** —— 要等 web 重启才生效。所以今天不算修好了，只算修对了。

### 真的那一层

`tick` 里第 1721 行，`windows[key] = true` 写在 `runDuty()` **前面**。开跑前就记账。

于是 `code=1` 和 `code=0` 在账本上长得一模一样。失败不吵、不重试、不留一句"我还会再来"——它只是安静地把那一班删掉了。这跟这两天那件事是同一个形状：**不是坏了没人修，是坏了以后账本替它说好话。**

改法：判定挪进 `lib/state.mjs` 的 `windowPlan()`，纯函数；**成功才置 done**（exit code === 0），失败记一次 attempt，冷却 10 分钟重试，最多 3 次，用完在日志里明说「今天不试了」。`bumpState` 的天翻页顺带清掉 attempts。

`test-window-plan.mjs` 12 条，全过。其中三条是这次改动的真判据：

- 失败一次、5 分钟前 ⇒ 冷却（不许马上再烧一轮）
- 失败一次、11 分钟前 ⇒ **重试**（这条以前不存在）
- 试满 3 次 ⇒ exhausted，并且要说出来

顺手把今天被老代码记成 done 的两班标记清了，重记成"各失败一次"。它们确实没跑成，账本没资格替它们说跑成了。
