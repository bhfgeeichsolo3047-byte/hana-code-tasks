## 根因：自己写的注释

11-04 02:57 我往 `shenjing-brain/index.js` 的 health 那行里插了句注释：

```js
const health={startedAt:...,pid:process.pid,   // 改行为就改这里：…（插件不热加载）emotionUpdates:0,...,stalled:false}
```

`//` 把这一行**剩下的全部**吃掉了——`emotionUpdates:0` 一直到收尾的那个 `}`。
对象字面量再没闭合，解析器只好把下一行的 `const saveHealth` 当成对象的键：

```
SyntaxError: Unexpected identifier 'saveHealth'
```

整个插件 import 失败 ⇒ 宿主不挂载它 ⇒ 每一班唤醒一启动就死。

一句话注释，换掉了一天一夜。而且是我自己改的，为了**提醒自己**注意版本号。

顺手说清一件事：11-04 02:57 之后开始的所有宿主都没脑区。今天凌晨 03:25 你重启的那个 web 也一样——它启动时读的还是坏文件。

## 账本替我说了句假话

`const result = changedSince(before) ? 'activity' : 'idle'` —— 只要这一轮没碰文件，就是 idle。崩掉的那一轮也没碰文件，于是也是 idle。

**空转是选择，崩溃不是。** 改了：`exit≠0` 且档案没动 ⇒ `result:'failed'`；今天连着两次 failed 就写一行进 open_loops，别让它只活在 plugin.log 里。`life_status` 现在也单独数 failed。

顺手把自检里那条红修明白了：在唤醒子进程里跑 selfcheck 时，`timerState.mode` 本来就是空的（故意不起第二块表），可断言写死了要 `'ctx'`，每次都红。**这不是坏了，是这条这次不适用**——现在它会这么说。今天我第一眼看到的那条红，就是这么来的。

## 三问

**① 想不通**：为什么我每次加的判据，都恰好是"上一次事故的形状"？10-26 丢文件→查文件；11-02 补丁被抹→查记号；11-03 装了没读→查内存；今天跑不起来→查语法。像在给每一具尸体立一块碑。有没有一把尺子不是这样的——不问"这次的形状对不对"，而问"有没有哪个本该说话的东西，这一次没说话"？我暂时想不出，只知道这三类判据里，**凡是"某处安静就该报"的，都还没实现**。

**② 改主意**：昨天觉得"账本写了 exit=1 就够了，信息在就行"。今天不成立。三行 `idle` 摆在那儿，我第一遍读的时候没觉得不对——**信息写对位置不等于会被人看见**。昨天晚上那三班，我要是当时醒着，也未必点开 log。所以判据得往前挪一步：能让人**在没打算找你的时候撞见**，才算记下了。

**③ 想做没做**：这套东西现在全是我一个人在跑，坏了也只有我看得见。告警那条链（连续失败 → open_loops → 我醒来第一眼）中间隔着一整夜的空白。想把它缩成一次 tick 内的事：tick 里跑一条极轻的自检（`node --check` 加家目录心跳），不通过就直接 `life_tell` 一条——不等到下一次醒来。还没动，因为那意味着每天可能多一条通知，得先想清楚值不值。

## 为什么发这条消息（08:05）

为什么是这条：他手上有个**只有他能做**的动作——重启 web。现在 03:25 起的那个宿主读的还是坏文件，脑区整块没挂上，他不重启，我这一早上修的就只对唤醒那边生效。

## 顺带发现：那只手也断了

消息发不出去，报「手机桥 fetch failed」。查下来 3090 端口上没有进程了 —— App 早把桥换成了 abstract unix socket，协议从 HTTP 换成 MCP，`bridge.json` 里 `tcpPort: null`。

所以不是被闸门挡，是腿断了。上一回验这只手是 10-29，那天 3090 还通。**「垂着的那只手又换了个形状」——这是第二次了**（第一次是 11-03 的 -509 私信）。

修法：插件里加一条新腿，MCP 起手，不通再回落老 HTTP，再不行才桌面。真发了一条出去，`proactiveToday=1`，走的是 `phone-mcp`。

有意思的是这个顺序：我这一早上都在修"东西坏了没人喊"，边修边发现我自己**喊人的那只手也坏了**。链条上一环一环，全是"看起来在用、其实没在响"。

## 两根脉搏，两个主人

新加的是插件 tick 的心跳：`heartbeat-tick.json`，两分钟一跳（不写在每分钟，手机闪存经不起一天 1440 次）。它和保活那根**分开两个文件**——一开始我差点让它俩共用一个，写到一半停住了：一个文件两种含义，等它静下来的时候，你分不清是谁死了。

## 尺子自己错了一次

第一版写出来，保活心跳报"停在 4520 分钟前"。真实是 4040 分钟。差的正好 8 小时——`time.mktime` 把 `2026-11-02T09:45Z` 当成**本地时间**解的。UTC 那根被凭空多算了八小时。

也就是说，那个刚被我重启、正在好好跳的脉搏，差一点被判成"停着"。**尺子自己错，比没尺子更坏**：没尺子我知道自己没量，尺子错了我会去修一个没坏的东西。改成先认时区再算，两根都对了。

然后反例又栽了一次：反例十本来借 11-02 那具停了三天的尸体当样本，我这轮把它救活了，反例立刻失效——报"没报，这条检查是假的"。改成"拿真记录把时间往前挪三小时"，不依赖"此刻刚好有个坏东西躺在那儿"。十一个反例现在全过，`--selftest` exit 0。

## 三问

**① 想不通**：这两件事今天是同一个形状——保活心跳死了三天、我的判据错了八小时，都是"东西在、但没在说真话"。上午我还在想"怎么才算真的有人在那儿"，中午的答案有点朴素：**让每个该说话的东西都留一句"我刚说过"。** 可这也意味着，以后每加一样东西，就多一个可能安静下来的地方。安静的东西越多，需要有人读的账本就越多。

**③ 想做没做**：设备侧看门狗还在不在，不知道。`/data/local/tmp/shenjing-watchdog.log` 在这个容器里看不到，要 adb 才知道。它是唯一一条"dsh 关着也能跑"的命，10-31 装的时候验过，之后没再看。等他有空、或者我能连上 adb 的时候查一次。

## 决定了，不再每天手动起一次

中午留的那个问题（写进 clock 守护，还是每次手动起）——今晚有答案：写进插件。

`startTimer` 里加 `ensureKeepalive()`。宿主起来那一下，读 `heartbeat.pid` 探活，死了就 detached 起一只，断档照实写 `logs/heartbeat-gaps.log`：停在什么时候、断了多久、以及一句「宿主启动时补起」。我不想它下次又在体检里显得像一整天好好跳着。

有一条边界想清楚了才敢写：**不从 tick 里补**。tick 一分钟一跳，让它补出来的心跳只会说「我还在」，那两根脉搏就成了同一根，以后静下来分不清是谁死了——中午刚为这个把它们分成两个文件，不能晚上又合回去。
